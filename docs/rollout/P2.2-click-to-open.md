# P2.2 · Click to open

[← Back to the overview](../README.md) · Step tracker: [rollout/](README.md) · Plan:
[P2.2](../03-rollout-plan.md#p22-click-to-open) · Before this: [P2.1 · Hover shows the panel](P2.1-hover-shows-panel.md)

Step 2 of [Phase P2](../03-rollout-plan.md#phase-p2-wire-it-together), and the last step of the feature itself.
Clicking a row in the panel opens that item, the same as double-clicking it in Finder. Then the panel hides. A
subfolder opens in a Finder window ([D8](../03-rollout-plan.md#decisions), decided 2026-11-24, answering
[Q5](../03-rollout-plan.md#open-questions)).

```
click a row ──▶ folder?  ── yes ─▶ open it in Finder (always Finder)         ─┐
                  │ no                                                         ├─▶ hide the panel, log "open: …"
                  └──────▶ file, app or package: its default app (NSWorkspace) ─┘
```

## What changed

| File | Change |
|---|---|
| [Sources/Glimpse/ItemOpener.swift](../../Sources/Glimpse/ItemOpener.swift) (new) | Files, apps and packages open in their default app. Folders open with Finder explicitly, so another app set as the default for folders doesn't take over ([D8](../03-rollout-plan.md#decisions)). Failures are logged. |
| [Sources/Glimpse/PreviewPanel.swift](../../Sources/Glimpse/PreviewPanel.swift) | Each row is a button covering the whole row, with a highlight under the cursor. The panel's view accepts the first click (see below). `onOpen` reports the clicked item. |
| [Sources/Glimpse/HoverController.swift](../../Sources/Glimpse/HoverController.swift) | On a click: open, then hide the panel. Developer helper `simulateClick(row:)`. |
| [Sources/Glimpse/AppDelegate.swift](../../Sources/Glimpse/AppDelegate.swift) | Developer option `--simulate-click <row>`, used together with `--simulate-hover`. |

## Why these choices

- **Accept the first click.** The panel never becomes the active window, so to AppKit every click on it is a "first
  click", which by default only brings a window forward. Without the override (`acceptsFirstMouse` → true) the first
  click on a row could do nothing.
- **Hide after opening.** The panel floats above other windows. Left open, it would cover the document or Finder
  window you just opened. To open another item, rest on the icon again.
- **Folders: Finder, explicitly.** "Open in Finder" was the choice ([D8](../03-rollout-plan.md#decisions)); a plain
  `open` would hand the folder to whatever app is the default for folders.
- **Still read-only ([D6](../03-rollout-plan.md#decisions)).** Opening is the only thing a click does. Nothing is moved,
  renamed or deleted, and there's no drag and drop.

## Check it yourself (2 minutes)

Glimpse is running (started 07:10 UTC). The rebuild cleared its Accessibility grant again: switch **Glimpse** back on
in System Settings → Privacy & Security → Accessibility.

1. Close Finder windows (**⌘W**; one opened during my test, showing a scratch folder called `alpha`), press
   **fn F11**, and rest on a desktop folder. Its panel opens ([P2.1 check](P2.1-hover-shows-panel.md#check-it-yourself-3-minutes)).
2. Move into the panel. The row under the cursor is highlighted.
3. **Click a file** once: it opens in its app, and the panel hides.
4. Rest on the folder again and **click a subfolder**: a Finder window opens on it, and the panel hides.
5. Paste:

   ```bash
   grep -E "hover|panel|open|unrecognised" ~/Library/Logs/Glimpse.log | tail -30
   ```

## Worth knowing

- **One click, not two.** A double-click opens the item once; the second click lands wherever the panel was, after it
  hid.
- **The highlight relies on SwiftUI's hover tracking inside a window that's never active.** If it doesn't show,
  clicking still works. Tell me and I'll switch it to AppKit tracking.
- **`--simulate-click` really opens the item**, so the test above opened a Finder window on a scratch folder.
