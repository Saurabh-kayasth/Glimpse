# P1.3 · Hover detection: which desktop folder is the cursor resting on

Step 3 of [Phase P1](../03-rollout-plan.md#phase-p1-building-blocks). While **Hover Previews** is on and Accessibility
is granted, Glimpse watches the cursor. When it rests on a desktop folder, Glimpse writes `hover: <path>` to its log.
**It doesn't open the panel yet**; that's [P2.1](../03-rollout-plan.md#p21-hover-shows-the-panel). Nothing on screen
changes.

**Built before the second P0 run (2026-11-24).** The first run proved the parts that decide the design (Finder names
icons by `AXURL`; the system-wide ask sees what's really on top), but it never reached a real desktop icon. This step's
own check, resting on the desktop icons, answers that, with the same evidence the probe would have logged. If desktop
icons turn out different, the fix is confined to [DesktopRules.swift](../../Sources/GlimpseCore/DesktopRules.swift).

```
every 50 ms: cursor moved? ── yes ─▶ start the 0.35 s rest clock
                  │ no, rested 0.35 s, not checked here yet, main screen, below the menu bar
                  ▼
  window list: front to back, skip Glimpse, Window Server, Dock layer 20 ──▶ Finder, layer < 0?  ── no ─▶ nothing
                  ▼
  system-wide "what's here?" (0.25 s time-out) ──▶ from Finder? ── no (Dock tile, widget, app) ─▶ nothing
                  ▼
  hit + up to 3 parents (+ children of small ones): AXURL / AXFilename / shown name ─▶ item in ~/Desktop?
                  │                                         full-screen group ─▶ empty desktop: nothing
                  │                                         anything else ─▶ "unrecognised …" (max 50 per launch)
                  ▼
  follow symlinks and aliases ──▶ a real folder (not .app)? ──▶ log "hover: <path>" (once per folder) ──▶ onHover
```

## How the design changed from the plan, and why

| Plan said | Built | Evidence |
|---|---|---|
| Step 3: skip our windows and Window Server's; first other window must be Finder below layer 0 | Also skip the **Dock's full-screen layer-20 window** | Rule as planned said "no, Dock layer 20" in all 180 probe samples |
| Step 4: ask Finder what's at the point | Ask **system-wide**, and require the answer to come from Finder | The system-wide ask returned `Dock AXDockItem` on the Dock tiles, where the window rule alone said "desktop showing" (28 samples). Asking Finder alone would see through windows in front. |
| Step 1: ignore points off the main screen | Also ignore the **menu bar** | Under the menu bar the window rule finds Finder's desktop; with Finder in front, its menu items would be logged as unrecognised |
| Step 4: if the hit is the label, step up to its parent | Up to 3 parents, **and the children of small elements** (≤ 200 × 200), so a label's group can point to the icon | In Finder windows a label hit was an `AXStaticText` inside an `AXCell`. On the desktop it's still to be seen. |

## Logging

| Line | When |
|---|---|
| `hover detection on` / `off` | Hover Previews or Accessibility changes |
| `hover: /Users/…/Desktop/Work [AXURL, 1.2 ms, at (1400, 90), icon (1380, 60, 64, 64)]` | The cursor rests on a folder; once per folder until it rests somewhere else |
| `unrecognised Finder element at (x, y): AXStaticText/ frame …` | A Finder element on the desktop that isn't an item or the background; **at most 50 per launch** |
| `check: nothing at (x, y): not Finder (AXDockItem), 0.9 ms` | Only with **Log Every Hover Check** on; at most 500 per launch |

## Check it yourself (3 minutes)

**Since [P2.1](P2.1-hover-shows-panel.md) this check is part of P2.1's**: a hover now opens the panel. The menu item
**Log Every Hover Check** became a setting: `defaults write local.glimpse.app verboseHoverLog -bool true`, then relaunch.

This rebuild cleared Glimpse's Accessibility grant, as every rebuild does.

1. Grant it again: System Settings → Privacy & Security → Accessibility → switch on **Glimpse**. The eye loses its
   badge.
2. Menu-bar eye → turn on **Log Every Hover Check**.
3. Close any Finder windows (**⌘W**), then press **fn F11** (or spread thumb and three fingers on the trackpad):
   **Show Desktop** slides every window to the edge. The desktop's own icons sit on the wallpaper, usually in a
   column at the right. A Finder window showing the Desktop folder doesn't count: Glimpse ignores Finder windows
   ([D5](../03-rollout-plan.md#decisions)).
4. Rest the cursor about 1 second on: each of the 6 desktop folders **on the icon**, then **on its name**; the
   **widget** at the top left; an **empty** bit of desktop; the **Dock**.
5. Run:

   ```bash
   grep -E "hover|check:|unrecognised" ~/Library/Logs/Glimpse.log | tail -40
   ```

   and paste the output here.

**What a pass looks like:** one `hover: …/Desktop/<folder>` line for each of the 6 folders, from the icon and from the
name, each a few ms. No `hover:` lines from the widget, empty desktop or Dock: they show as `check: nothing …`. No, or
only a few, `unrecognised` lines; any there tell us exactly what Finder said.

## Worth knowing

- **Detection runs on the main thread.** Each check took about 1 ms in the probe (39 ms at most). With the 0.25 s
  time-out a stuck Finder could make the menu feel slow for a moment, but not freeze it.
- **One check per resting point.** A cursor that stays still costs only reading its position 20 times a second.
- **"Hover" is logged once per folder.** Resting on the icon and then its name gives one line; leaving and coming back
  gives another.
- **Reading desktop names** (only for the shown-name fallback) uses the Desktop folder permission granted in
  [P1.2](P1.2-preview-panel.md#worth-knowing).
