# P4.1 · All screens

[← Back to the overview](../README.md) · Step tracker: [rollout/](README.md) · Plan:
[P4.1](../03-rollout-plan.md#p41-all-screens) · Before this: [P3.1 · Launch at login](P3.1-launch-at-login.md)

Step 1 of [Phase P4](../03-rollout-plan.md#phase-p4-other-screens). Until now Glimpse only worked on the main screen
([D1](../03-rollout-plan.md#decisions), as first decided). It now works on **whichever screen the cursor is on**, and
keeps the panel on the icon's own screen. Decided 2026-11-24 when you asked for it. **On a single screen nothing
changes**; this Mac had only the built-in display connected while it was built.

```
cursor (Cocoa) ──▶ which screen? (ScreenMath.screen) ── none ─▶ stop
                        │ that screen's menu bar? ── yes ─▶ stop
                        ▼
          to Quartz with the MAIN screen's height ──▶ window rule + Accessibility (unchanged; global coordinates)
                        │ empty desktop = a Finder group the size of THIS screen
                        ▼
          icon's screen ──▶ panel inside that screen's usable area (never across the edge onto a neighbour)
screens added / removed / rearranged ──▶ hide the panel
```

## The one idea

macOS puts all screens in **one coordinate space measured from the main screen** (the one with the menu bar in System
Settings → Displays → Arrange). A screen to the left has negative x; a screen above has Cocoa y beyond the main
screen's height, which is negative in Quartz. So the conversion Glimpse already used, Quartz y = main height − Cocoa y,
is right for every screen, **as long as it always uses the main screen's height**. The parameter is now called
`mainScreenHeight` so that can't be mixed up. What had to change were the places that assumed *the* screen:

| Place | Before | Now |
|---|---|---|
| [HoverDetector.swift](../../Sources/Glimpse/HoverDetector.swift) | ignore points off the main screen; skip the main screen's menu bar | find the screen under the cursor; skip **its** menu bar (a screen without one never skips) |
| [DesktopHitTest.swift](../../Sources/Glimpse/DesktopHitTest.swift) | "empty desktop" = a Finder group the size of the main screen | the size of the screen under the cursor |
| [HoverController.swift](../../Sources/Glimpse/HoverController.swift) | panel inside the main screen's usable area | inside the **icon's** screen's usable area; refuses (and logs) an icon on no screen; hides when screens change |
| Log | `at (x, y)` | `at (x, y) on <screen name>`, to tell screens apart when testing |

## Check it yourself (with an external display)

Glimpse is running the new build and is still granted, thanks to [P3.2](P3.2-stable-signing.md).

1. Connect the display. The panel, if open, hides ("screens changed").
2. Put a folder on the desktop of the external display (drag one there in Finder, or arrange icons so some land
   there), then **fn F11** to show the desktop.
3. Rest on it: the panel opens **beside it, on the external display**, fully visible.
4. Rest on a folder on the built-in display: works as before.
5. Rest on the external display's menu bar and its empty desktop: nothing.
6. Optional: in System Settings → Displays → Arrange, move the external display to the other side or above, and
   repeat 3.
7. Paste: `grep -E "hover:|panel|isn't on any screen|screens changed|unrecognised" ~/Library/Logs/Glimpse.log | tail -20`

## Worth knowing

- **What couldn't be tested here.** Only the built-in display was connected, so these are unknown on a real second
  screen: whether Finder's desktop window, the Dock's layer-20 window and a Window Server strip exist **per screen**.
  The rules handle any of them per point, the same as on the built-in display, and an unexpected window shows in the
  log as `desktop not showing (<owner> layer <n>)` with detailed logging on.
- **"Displays have separate Spaces"** (System Settings → Desktop & Dock) gives each screen its own menu bar. When it's
  off, only the main screen has one, and the other screens' tops are usable. Both cases are covered.
- **Hiding when screens change** avoids a panel left floating at a spot that no longer makes sense after a display is
  unplugged or rearranged.
