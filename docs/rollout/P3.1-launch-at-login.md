# P3.1 · Launch at login

[← Back to the overview](../README.md) · Step tracker: [rollout/](README.md) · Plan:
[P3.1](../03-rollout-plan.md#p31-launch-at-login) · Before this: [P3.2 · A grant that survives rebuilds](P3.2-stable-signing.md)

Step 1 of [Phase P3](../03-rollout-plan.md#phase-p3-daily-use), built after P3.2. The menu has a **Launch at Login**
switch, which uses macOS's own login-item service. To make that dependable, `./build.sh` now **installs Glimpse to
`~/Applications/Glimpse.app`** and runs it from there, and only one Glimpse can run at a time. **It's off until you
switch it on.**

```
./build.sh --run ──▶ build + sign in build/ ──▶ install ~/Applications/Glimpse.app (build/ copy removed) ──▶ open it
menu "Launch at Login" ──▶ SMAppService.mainApp.register() ──▶ System Settings → Login Items lists Glimpse
                                                           └─▶ needs approval? opens that page
next login ──▶ macOS starts ~/Applications/Glimpse.app ──▶ already granted (P3.2) ──▶ previews work
```

## What changed

| File | Change |
|---|---|
| [Sources/Glimpse/LoginItem.swift](../../Sources/Glimpse/LoginItem.swift) (new) | On/off and status through `SMAppService.mainApp`. Opens System Settings → Login Items when macOS wants approval. Offered only when running from `/Applications` or `~/Applications`. |
| [Sources/Glimpse/AppDelegate.swift](../../Sources/Glimpse/AppDelegate.swift) | Menu item **Launch at Login** (✓ when on; greyed out with a hint when running from elsewhere). **One Glimpse at a time:** a second copy logs why and quits. The launch log line now also shows where the app runs from and the login-item status. |
| [build.sh](../../build.sh) | After signing, installs to `~/Applications/Glimpse.app` and removes the staging copy in `build/`. `--run` starts the installed copy. |

## Why install to ~/Applications

- **The login item points at one place.** macOS records the app where it was registered. `build/Glimpse.app` is
  deleted and recreated on every build, and the folder is ignored by git, so it's a poor place for something that
  starts at login.
- **`~/Applications`, not `/Applications`:** it's yours, so no admin password is needed, and it's still where macOS
  expects apps.
- **No second copy.** Two copies with the same id could both run and open two panels per hover; the staging copy is
  removed after installing, and the app refuses to run twice anyway.
- **Permissions carry over.** macOS identifies the app by its signature ([P3.2](P3.2-stable-signing.md)), not its
  location. The installed copy started already granted.

## Check it yourself (2 minutes)

1. Menu-bar eye → **Launch at Login**. macOS may show a "Login Item Added" notification. If the item reads
   "approve in System Settings…", switch **Glimpse** on in the page that opens (General → Login Items &
   Extensions).
2. Open the menu again: **Launch at Login** is ticked.
3. Log out ( → Log Out) and log back in, or restart.
4. The eye is in the menu bar without you starting anything. Rest on a desktop folder: the panel opens.
5. Paste: `grep -E "launch|login" ~/Library/Logs/Glimpse.log | tail -5`

To switch it off: untick **Launch at Login**, or switch it off in System Settings → General → Login Items &
Extensions.

## Worth knowing

- **Run Glimpse from `~/Applications` from now on.** The README's `./build.sh --run` does that. Opening an old copy
  from elsewhere shows Launch at Login greyed out.
- **The login item survives rebuilds**: same path, same signature.
- **The slow-check fix** from the [desktop test](P2.1-hover-shows-panel.md#real-desktop-test-2026-11-24-07310739-utc)
  ships in this build: after the first Accessibility time-out a check stops ("Finder busy"), instead of freezing for
  up to 2.4 s.
