# P0.1 + P0.2 · A probe that asks Finder what's under the cursor

[← Back to the overview](../README.md) · Step tracker: [rollout/](README.md) · Plan:
[P0.1](../03-rollout-plan.md#p01-ask-finder-what-is-under-the-cursor),
[P0.2](../03-rollout-plan.md#p02-is-the-desktop-showing-at-this-point)

Both steps of [Phase P0](../03-rollout-plan.md#phase-p0-prove-it) in one throwaway app. Once a second it notes where
the cursor is, which windows are under it, and what Finder says is there. It writes all of that to a log, then quits
on its own. A small script reads the log and says pass or fail. **It's a separate app, not part of Glimpse, and it
changes nothing on the Mac.** It only reads.

**Status (2026-11-24): first run done, partly answered.** Finder names icons with a full path, and the system-wide
ask sees through the Dock's window. But the run never reached a **real desktop icon**: the desktop stayed covered by
full-screen app windows, and the folder hits came from a Finder window showing `~/Desktop`. See
[first run](#first-run-2026-11-24-0559-utc). A second, shorter run on the bare desktop is still needed.

```
every 1 s:  cursor ──▶ windows under it, front to back ──▶ rule as planned:   yes / no
                                                       └─▶ rule skipping Dock: yes / no
                   ──▶ ask the whole system "what's here?"  ─┐
                   ──▶ ask Finder alone "what's here?"      ─┴▶ element + up to 3 parents
            ──▶ one JSON line in ~/Library/Logs/Glimpse-probe.log
afterwards: check-log.py + names in ~/Desktop ──▶ per-folder table + verdict
```

## Found while building: the Dock covers the whole screen

The first test run (2026-11-24, `--no-ax`, cursor over VS Code) listed this window in front of everything under the
cursor:

```
{'owner': 'Dock', 'layer': 20, 'bounds': [0, 0, 1470, 956], 'alpha': 1, ...}   ← in front of VS Code (layer 0)
```

It was there in every check, window number 12 each time. It's most likely the see-through window the Dock draws itself
in. It changes the plan in two places:

- **P0.2:** the rule as planned ("skip our windows and Window Server's; the first other one must be Finder's below
  layer 0") would answer "no" at every point. The probe logs that rule **and** a version that also skips the Dock's
  layer-20 window. Only the second can pass. Recorded in [01](../01-current-macos-desktop.md#the-desktop-is-a-stack-of-windows)
  and [Q2](../03-rollout-plan.md#open-questions).
- **P0.1:** a system-wide "what's at this point?" might also stop at the Dock's window. So the probe also asks
  **Finder alone** (`AXUIElementCreateApplication(finderPID)`). Finder then looks only inside its own elements. If only
  the Finder-alone answer works, Glimpse uses that. The window-list check in step 3 is what makes it safe to ignore
  windows in front.

## Why it's its own app

Accessibility is granted to an app, not to a command. A command run from VS Code's terminal counts as VS Code, so
granting it would give the power to read and control other apps to VS Code **and every extension in it**. Started with
`open`, the probe is its own app, and the grant goes to `local.glimpse.probe` alone.

## What it logs, and what it never logs

- **Finder's elements:** role, subrole, title, description, identifier, `AXFilename`, `AXValue`, `AXURL`, position and
  size, for the element and up to 3 parents. The first time it sees each kind of element, it also logs every attribute
  Finder offers for it. That answers what else is there besides what we guessed.
- **Other apps' elements** (VS Code, Chrome…): **only the app name and the role** (for example `Code AXGroup`). No
  titles, values or text, following [safety rule 2](../02-design.md#safety-rules).
- **Windows under the cursor:** owner, layer, alpha and bounds. No window names.
- Nothing leaves the Mac. The log is a local file you can delete at any time.

## Run it (you, 10 minutes)

1. Start it from VS Code's terminal:

   ```bash
   cd Glimpse
   tools/ax-probe/build.sh --run --seconds 180
   ```

   To watch what it sees while you move the cursor, run this in a second terminal (Ctrl-C to stop):

   ```bash
   python3 tools/ax-probe/check-log.py --live
   ```

2. macOS asks to give **GlimpseProbe** Accessibility. Open System Settings → Privacy & Security → Accessibility and
   switch on **GlimpseProbe**. Not VS Code. You hear **"Tink"** when sampling starts; from then you have 180 s.
3. Rest the cursor on each spot for **about 4 seconds** (at least 3 samples), in this order:
   1. a **VS Code window** (this one);
   2. then clear the desktop: in VS Code press **⌥⌘H** (hide others), then **⌘H** (hide VS Code);
   3. each of the **6 desktop folders**: first **on the icon**, then **on the name below it**. The top one is the
      top-row test for P0.2;
   4. an **empty bit of desktop**;
   5. the **widget at the top left**;
   6. a **Finder window**: click the desktop, press **⌘N**, rest on a folder in that window.
4. You hear **"Glass"** when it's done (or quit early: `pkill -x GlimpseProbe`).
5. Read the result:

   ```bash
   python3 tools/ax-probe/check-log.py
   ```

   Paste the output into the chat. I'll interpret it and finish this doc.

**What a pass looks like:** in the per-folder table, all 6 folders get ✓ under **Finder-only** (or system-wide) and
under the **skip-Dock rule**. In the spot list, the **pipeline** column shows a folder name only on the icon spots.
It shows `—` on VS Code, the empty desktop, the widget and the Finder window.

**Afterwards:** remove the grant (System Settings → Accessibility → select GlimpseProbe → **−**), or run
`tccutil reset Accessibility local.glimpse.probe`.

## Worth knowing

- **Each rebuild needs a new grant.** `build.sh` clears the old one on purpose, so macOS asks again instead of
  silently ignoring a stale entry ([D4](../03-rollout-plan.md#decisions)).
- **The grant takes effect without a restart.** The probe checks once a second and starts sampling as soon as you
  switch it on.
- **Swift 5 language mode** (`-swift-version 5`), because the Accessibility constants are C globals that Swift 6's
  strict concurrency checks reject. The real app ([P1.1](../03-rollout-plan.md#p11-app-skeleton)) will need the same
  setting or small wrappers.
- **Plan change:** 120 s by default instead of the planned 60 s (16 spots × about 4 s don't fit in 60). The run above
  uses 180 s to leave time for the grant.

## What this doesn't cover

- A second screen ([D1](../03-rollout-plan.md#decisions); there is only one).
- Desktop icons arranged by hand instead of by name, or a different icon size: the boxes might differ.
- Finder windows in icon view vs. list view: the run checks one Finder window, enough to show the rule rejects it.
