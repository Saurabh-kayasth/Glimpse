# P3.2 · A grant that survives rebuilds

[← Back to the overview](../README.md) · Step tracker: [rollout/](README.md) · Plan:
[P3.2](../03-rollout-plan.md#p32-a-grant-that-survives-rebuilds) · Before this: [P2.2 · Click to open](P2.2-click-to-open.md)

Step 2 of [Phase P3](../03-rollout-plan.md#phase-p3-daily-use), built before step 1 at your request. Glimpse is now
signed with a local certificate, **"Glimpse Local"**, instead of ad hoc. macOS therefore sees every new build as the
same app, and **Accessibility stays granted after a rebuild**. Until now, every rebuild had silently voided the grant.
Decided 2026-11-24 ([D4](../03-rollout-plan.md#decisions), answering [Q4](../03-rollout-plan.md#open-questions)).

```
before:  signed ad hoc  ──▶ macOS's name for the app = a fingerprint of this exact build ──▶ new build = new app
now:     signed with "Glimpse Local" ──▶ name = identifier "local.glimpse.app" and certificate root = H"e19916…308d"
                                     ──▶ new build, same name ──▶ the grant still applies
```

## What changed

| File | Change |
|---|---|
| [tools/make-signing-cert.sh](../../tools/make-signing-cert.sh) (new) | Run once. Makes the self-signed code-signing certificate "Glimpse Local" (RSA 2048, valid 10 years) and imports it into the login keychain. Only `codesign` may use its key without asking. The key file is deleted right after import. Does nothing if the certificate already exists. |
| [build.sh](../../build.sh) | Signs with "Glimpse Local" when it's there and **no longer clears the grant**. Without it, it falls back to ad hoc and clears the grant as before. New `--reset-grant` to clear it on purpose. Stamps each build with a build number (UTC time). |
| [Sources/Glimpse/AppDelegate.swift](../../Sources/Glimpse/AppDelegate.swift) | The launch log line shows the build number: `launch: Glimpse 0.1.0 (build 20261124.072700) …`. |

## Why a self-signed certificate

- **It's free and stays on this Mac.** It isn't tied to an Apple developer account. The Apple Development and
  Distribution certificates already in this keychain belong to other people's and companies' teams; using one would
  tie the project to that team and its expiry.
- **It doesn't need to be trusted.** macOS lists it as `CSSMERR_TP_NOT_TRUSTED`, which is normal for a self-signed
  certificate. `codesign` signs with it anyway, and no password prompt or trust change was needed. What matters to
  macOS's permissions is the signature's *designated requirement* (the bundle id plus the certificate's hash), and
  that stays the same across builds.
- **What it can't do:** other Macs don't trust it, and Apple can't notarize with it. Sharing Glimpse with others still
  needs a Developer ID ([see the sharing notes](#worth-knowing)).

## Worth knowing

- **One last grant was needed** when switching from ad hoc to the certificate, because that changed how macOS names
  the app. From now on, rebuilds keep it.
- **If the certificate is deleted**, `build.sh` falls back to ad hoc and says so. Grants go back to resetting on every
  build until you run `tools/make-signing-cert.sh` again; that makes a new certificate, so you grant once more.
- **To force a fresh prompt** (for example to test first-launch behaviour): `./build.sh --run --reset-grant`.
- **Sharing with other Macs** still needs Apple's Developer ID signing and notarization (Apple Developer Program,
  $99/year). That's a separate step, not planned yet.
- **Desktop folder access** is a permission of the same kind. It should now persist across rebuilds too, but that
  wasn't tested separately.
