# P1.2 · Preview panel: a folder's contents in a floating panel

[← Back to the overview](../README.md) · Step tracker: [rollout/](README.md) · Plan:
[P1.2](../03-rollout-plan.md#p12-preview-panel) · Before this: [P1.1 · App skeleton](P1.1-app-skeleton.md)

Step 2 of [Phase P1](../03-rollout-plan.md#phase-p1-building-blocks). Glimpse can now show a folder's contents in a
floating panel that never takes focus from the app you're using. **Only the temporary "Test Panel" menu opens it.
Nothing opens it on hover yet**; that's [P2.1](../03-rollout-plan.md#p21-hover-shows-the-panel).

```
menu: Test Panel ▸ Work     ──▶ FolderListing.list(folder)      hidden skipped, folders first, Finder's name order
                                    │ items / empty / can't read
                                    ▼
                               PreviewPanel.show ──▶ non-activating floating panel, centred on the main screen
                                                     header + up to 12 rows, then it scrolls
```

## The panel

| Part | What it shows |
|---|---|
| Header | Folder icon, folder name, item count ("47 items") |
| Rows | File icon, name (long names cut in the middle), size for files in Finder's units (1 KB = 1000 bytes) |
| Order | Folders first, then files, each by name the way Finder sorts (`localizedStandardCompare`: case ignored, "Beta 2" before "Beta 10") |
| Size | 300 points wide. Header + up to 12 rows (316 points tall), then the list scrolls |
| Empty folder | "Empty folder" |
| Unreadable folder | "Can't read this folder" (for example no permission, or the Desktop folder permission was refused) |

Layout is a list, as proposed in [Q6](../03-rollout-plan.md#open-questions). An icon grid is still possible if you
prefer it.

## Why these choices

- **Test Panel lists the desktop folders in the menu instead of opening a file picker.** A picker is a dialog, so it
  makes Glimpse the active app and you can't tell whether the panel took focus. Choosing from the menu doesn't
  activate Glimpse, so the test is fair. **Other Folder…** still uses a picker, and hands focus back to the previous
  app before showing the panel.
- **`orderFrontRegardless()`** shows the panel without activating Glimpse; together with `.nonactivatingPanel` and
  `becomesKeyOnlyIfNeeded`, your app keeps the keyboard.
- **Packages count as files.** Finder shows `Something.app` as one item named "Something", not as a folder; so does
  the panel. Their size isn't shown (it would mean adding up everything inside).

## Tests (2026-11-24)

Test folders made in the scratchpad (not in the repo): **Big Folder** with 47 visible items (10 folders named to test
the order, 35 text files of 3–105 KB, a 5 MB file, a fake `Fake.app`) plus 2 hidden files; **Empty**; **Locked**
(`chmod 000`). Each was opened with Glimpse in the background, so the test could check that it stays there:

```bash
cd Glimpse
./build.sh
open -g build/Glimpse.app --args --test-panel "<folder>" --snapshot /tmp/panel.png   # -g: don't bring it forward
```

| Check | Result |
|---|---|
| Clean build, Swift 6 mode | ✅ 0 warnings |
| 47-item folder: header and rows | ✅ "Big Folder · 47 items"; 10 folders first (`alpha, Beta 2, Beta 10, Delta, …, Zeta`), then `big video.mov 5 MB`, `Fake` (no size), `file 1.txt` … in number order; hidden files not shown |
| Panel size and place | ✅ 300 × 316 points, centred on the main screen (x 585), window layer 3 (floating) |
| Empty folder | ✅ "Empty · 0 items", "Empty folder", 300 × 96 points |
| Unreadable folder | ✅ "Can't read this folder"; logged `panel: can't read folder (… you don't have permission to view it.)` |
| Doesn't take focus | ✅ in all three tests Glimpse was never the active app, and the app you were in (Chrome, then System Settings) stayed in front |

| **You:** the real 47-item desktop folder, scrolling with the trackpad, the Desktop permission prompt | ❓ [check it](#check-it-yourself-3-minutes) |

**A bug found and fixed while testing:** the first panels were drawn shifted right, with the header cut off. The list
was added to its background view while the background was still 0 × 0. When the panel then sized the background to
300 points, the list grew by the same 300 and ended up 600 wide. The background now gets its size first
([PreviewPanel.swift](../../Sources/Glimpse/PreviewPanel.swift)).

## Check it yourself (3 minutes)

**Since [P2.1](P2.1-hover-shows-panel.md) the Test Panel menu is gone**: the panel opens on hover instead, so check it
there. The steps below are kept as the record of how P1.2 was checked.

Glimpse is running (started at 06:13 UTC; if not, `open build/Glimpse.app`). Stay in VS Code while you do this.

1. Menu-bar eye → **Test Panel**. The first time, macOS asks whether Glimpse may access files in your Desktop folder:
   click **Allow**. The submenu then lists your 6 desktop folders.
2. Choose the 47-item folder. The panel opens in the middle of the screen: **47 items**, folders first.
   **VS Code stays the active app**: its name stays at the top left of the menu bar.
3. Scroll the panel with the trackpad; it scrolls to the last item.
4. **Test Panel → Other Folder…**, pick an empty folder (make one anywhere): "Empty folder".
5. Menu → **Hide Panel**.

## Worth knowing

- **The Desktop permission** is asked the first time Glimpse reads anything in `~/Desktop`, which now happens when you
  open the Test Panel submenu. If you refuse it, the submenu says "Can't read the Desktop folder" and panels say
  "Can't read this folder". To ask again: `tccutil reset SystemPolicyDesktopFolder local.glimpse.app`.
- **Until [P3.2](P3.2-stable-signing.md) (fixed 2026-11-24), any rebuild cleared the Accessibility grant**, not just `./build.sh`: re-signing ad hoc makes it a new app to
  macOS ([P1.1 · Worth knowing](P1.1-app-skeleton.md#worth-knowing)). I rebuilt several times while testing this
  step, so if you granted it in between, grant it again.
- **A test launch needs a pause after quitting.** Calling `open … --args` right after `pkill` started Glimpse without
  its launch options once; waiting a second fixed it.
- **The `--snapshot` image is taken 0.5 s after the panel opens.** The scrolling list isn't laid out before that, and
  an earlier snapshot shows it in the wrong place. The image has no frosted background, because a view snapshot
  can't capture what's behind the window.
