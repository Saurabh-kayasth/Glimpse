# P1.1 · App skeleton: menu-bar icon, menu, build script

[← Back to the overview](../README.md) · Step tracker: [rollout/](README.md) · Plan:
[P1.1](../03-rollout-plan.md#p11-app-skeleton) · Before this: [P0 probe](P0.1-ax-probe.md)

Step 1 of [Phase P1](../03-rollout-plan.md#phase-p1-building-blocks). Glimpse now exists as an app: an eye icon in
the menu bar with a small menu, no Dock icon. On first launch it asks for Accessibility. **It doesn't watch the cursor
or open panels yet, so the Mac behaves exactly as before.** Quit it from the menu and it's gone.

```
./build.sh --run ──▶ swift build -c release ──▶ build/Glimpse.app ──▶ sign ad hoc ──▶ clear old grant ──▶ open
                                                                                                          │
launch ──▶ log "launch …" ──▶ eye icon in the menu bar ──▶ not granted? ask macOS (prompt) ◀───────────────┘
              every 2 s: granted / removed? ──▶ update icon + menu, log it
```

## The menu

| Item | What it does |
|---|---|
| **Hover Previews** ✓ | On/off, remembered between launches (`hoverPreviewsEnabled` in the app's defaults). Nothing reads it yet; [P1.3](../03-rollout-plan.md#p13-hover-detection) will. |
| **Accessibility: granted** (greyed) / **Grant Accessibility Access…** | When not granted: shows macOS's prompt and opens System Settings → Privacy & Security → Accessibility. |
| **Show Log** | Opens `~/Library/Logs/Glimpse.log` (in Console). |
| **Quit Glimpse** ⌘Q | Quits; the icon goes away. |

The icon tells the state at a glance: `eye` (previews on), `eye.slash` (off), `eye.trianglebadge.exclamationmark`
(needs Accessibility).

## Why these choices

- **AppKit `NSStatusItem`, not SwiftUI's `MenuBarExtra`.** The next steps need AppKit anyway (a non-activating
  `NSPanel` in [P1.2](../03-rollout-plan.md#p12-preview-panel), Accessibility calls in
  [P1.3](../03-rollout-plan.md#p13-hover-detection)), and the status item gives full control over the icon and menu.
- **Swift 6 language mode**, unlike the probe. The one C global it tripped over (`kAXTrustedCheckOptionPrompt`) is
  written out as its value, `"AXTrustedCheckOptionPrompt"`. Everything runs on the main thread (`@MainActor`).
- **Check the permission every 2 s.** The grant happens in System Settings, and macOS doesn't tell the app. The check
  (`AXIsProcessTrusted()`) is a local call; the menu also re-checks each time it opens.

## Check it yourself (2 minutes)

If Glimpse isn't running: `open build/Glimpse.app` (keeps any grant), or `./build.sh --run` (rebuilds, clears it).

1. macOS showed "Glimpse would like to control this computer using accessibility features". Click **Open System
   Settings** and switch on **Glimpse**. If you closed the prompt, use the menu's **Grant Accessibility Access…**.
2. Within 2 seconds the icon changes from the eye with a warning badge to a plain **eye**. The menu now says
   **Accessibility: granted**.
3. Click **Hover Previews**: the icon becomes `eye.slash`; click again to turn it back on.
4. **Show Log** opens the log with lines like `accessibility granted` and `previews off`.
5. **Quit Glimpse**: the icon goes away and the log ends with `quit`.

## Worth knowing

- **Fixed in [P3.2](P3.2-stable-signing.md) (2026-11-24): grants now survive rebuilds.** Before that: **every `./build.sh` needed a new grant**, because ad-hoc signing makes each build a new app to macOS. The script
  clears the old entry so it doesn't linger. Lasting fix: [P3.2](../03-rollout-plan.md#p32-a-grant-that-survives-rebuilds)
  ([Q4](../03-rollout-plan.md#open-questions)). Just relaunching (`open build/Glimpse.app`) keeps the grant.
- **A switched-on entry can still do nothing (seen 2026-11-24).** If the app is re-signed without clearing its old
  entry (for example by copying a new binary into `build/Glimpse.app` instead of running `./build.sh`), System
  Settings keeps one "Glimpse" entry that belongs to the old build. Switching it on doesn't reach the running copy:
  the icon keeps its warning badge, and the log never says `accessibility granted`. Fix:
  `tccutil reset Accessibility local.glimpse.app`, restart Glimpse, switch it on again. Always rebuild with
  `./build.sh`, which clears the entry for you.
- **On macOS 26, menu-bar icons belong to Control Centre** in the window list. Anything that looks for "Glimpse's
  windows" by owner (like the skip rule in [02 step 3](../02-design.md#the-flow-step-by-step)) won't see the icon
  that way. That doesn't matter: the icon is in the menu bar, not over the desktop.
- **The notch.** This display has a notch in the middle of the menu bar. When the menu bar is full, macOS hides icons
  that don't fit, with no warning. Glimpse's icon fits today at x 1004. If it ever goes missing, quit another
  menu-bar app.
- **`pkill` skips the `quit` log line**; quitting from the menu writes it.
