# P5.1 · Finder windows in icon view

[← Back to the overview](../README.md) · Step tracker: [rollout/](README.md) · Plan:
[P5.1](../03-rollout-plan.md#p51-finder-windows-in-icon-view) · Before this: [P4.1 · All screens](P4.1-all-screens.md)

Step 1 of [Phase P5](../03-rollout-plan.md#phase-p5-finder-windows). Rest the cursor on a folder **inside a Finder
window shown as icons** and its panel opens beside it, the same as on the desktop. List, column and gallery views, the
sidebar and the toolbar are left alone. Decided 2026-11-24 ([D5](../03-rollout-plan.md#decisions), was "desktop
only"). A new menu switch, **Finder Windows** (on by default), turns the window part off.

```
window list ──▶ surface: desktop │ Finder window │ other ─▶ nothing
                    │                  │ (Finder Windows off ─▶ nothing)
                    ▼                  ▼
   desktop rules (unchanged)    icon-view rule: an AXImage with a file AXURL, and an AXList/AXCollectionList in the
                                chain (hit + up to 3 parents; a label reaches the image through its group's children)
                                    │ list / column view, sidebar, toolbar ─▶ "not icon view: <roles>" (detailed log)
                                    ▼
              a real folder anywhere (not .app) ──▶ panel beside it, on its screen (P2.1, P4.1 unchanged)
```

## Built from what the probe recorded

Your [first probe run](P0.1-ax-probe.md#first-run-2026-11-24-0559-utc) rested on a Finder window in icon view, so it
recorded exactly what Finder reports there. Every icon looked the same:

| Under the cursor | Chain (hit › parents) | Samples |
|---|---|---|
| **An icon** | `AXImage` with `AXURL`, 64 × 64 › `AXGroup` › `AXList/AXSectionList` › **`AXList/AXCollectionList`** | 39 |
| Empty space | `AXList/AXCollectionList` › `AXScrollArea` › `AXSplitGroup` › … | 15 |
| Sidebar | `AXStaticText` › `AXCell` › `AXRow/AXOutlineRow` › **`AXOutline`** | 1 |
| Title bar | `AXStaticText` › `AXWindow/AXStandardWindow` › `AXApplication` | 4 |

So the rule is: **an image with a real path, inside a collection list.** List and column views are built from rows,
and the sidebar is an outline. None of them has a collection list in the chain, so they're left out without having to
recognise each one.

## Check it yourself (3 minutes)

Glimpse is running the new build. Turn on detailed logging if it isn't (it is, from earlier):
`defaults read local.glimpse.app verboseHoverLog` should print `1`.

1. Open a Finder window on a folder with subfolders, in **icon view** (**⌘1**).
2. Rest on a subfolder's icon: its panel opens beside it. Try a name too. Move away: it hides.
3. Switch the window to **list view** (**⌘2**), **column view** (**⌘3**), **gallery view** (**⌘4**) and rest on
   folders: nothing should open.
4. Rest on a sidebar item and the toolbar: nothing.
5. Menu-bar eye → untick **Finder Windows**; icon view now does nothing, while the desktop still works. Tick it again.
6. If you open folders in **Documents** or **Downloads**, macOS asks once whether Glimpse may read them: **Allow**.
7. Paste: `grep -E "hover:|Finder window|finder windows|unrecognised" ~/Library/Logs/Glimpse.log | tail -30`

## Worth knowing

- **Gallery view may count as icon view.** Its strip of thumbnails might be a collection list too; the probe never
  saw gallery view. Step 3 above will tell. If it does count, the rule gets one more condition.
- **Scrolling the window under an open panel** doesn't move the panel. It hides as soon as the cursor leaves the
  icon's old spot and the panel.
- **Folders anywhere means more permission prompts**: the first folder read in Documents, Downloads, iCloud Drive, an
  external or a network drive each asks once. Saying no just shows "Can't read this folder".
- **Still read-only** ([D6](../03-rollout-plan.md#decisions)).
