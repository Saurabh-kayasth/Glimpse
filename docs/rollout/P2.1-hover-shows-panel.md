# P2.1 · Hover shows the panel

[← Back to the overview](../README.md) · Step tracker: [rollout/](README.md) · Plan:
[P2.1](../03-rollout-plan.md#p21-hover-shows-the-panel) · Before this: [P1.3 · Hover detection](P1.3-hover-detection.md),
[P1.2 · Preview panel](P1.2-preview-panel.md)

Step 1 of [Phase P2](../03-rollout-plan.md#phase-p2-wire-it-together). **This is the feature.** Rest the cursor on a
folder on the desktop and, after about 0.4 s, its panel opens beside the icon. Move into the panel to scroll it. Move
away from both and it hides 0.2 s later. The temporary test items from P1.2 and P1.3 are gone from the menu.

```
HoverDetector (P1.3) ── folder + icon box ──▶ HoverController.hovered
                                                │ keep zone = icon + label + 24 pt each side
                                                │ PanelPlacement.frame: right of the zone if it fits, else left;
                                                │                       top = icon's top, kept inside the usable area
                                                ▼
                                         PreviewPanel.show (P1.2) ──▶ "panel shown N ms after the cursor stopped"
                                                │
                     every 50 ms while shown:  cursor in zone or panel? ── no for 0.2 s ──▶ hide
                     also hides on: Space change, Hover Previews off, Accessibility removed
```

## Where the panel goes

| Icon | Panel | Why |
|---|---|---|
| Near the right edge (the usual place for desktop icons) | **Left** of the icon | It doesn't fit on the right |
| Anywhere else | **Right** of the icon | Reading direction |
| Near the bottom | Pushed **up** to sit above the Dock | Stays inside the usable area (y 51…923) |
| Under the menu bar | Pushed **down** | Same |

The panel starts right next to the **keep zone**: the icon plus 24 points on each side, 44 below for the label and 8
above. So it never covers the icon or its name, and there's no gap to cross when you move into it. The panel hides
once the cursor has been outside both the zone and the panel for 0.2 s ([D7](../03-rollout-plan.md#decisions)).

## Check it yourself (3 minutes)

Glimpse is running (started 07:03 UTC). This rebuild cleared its Accessibility grant again.

1. System Settings → Privacy & Security → Accessibility → switch on **Glimpse**. The eye loses its badge.
2. Close any Finder windows (**⌘W**), then press **fn F11**: windows slide away and the desktop's icons show on the
   wallpaper.
3. Rest the cursor on a folder icon. **Within about half a second its panel opens beside it.** The first time, macOS
   may ask about the Desktop folder again (rebuilds can reset that too): click **Allow**, then rest on it again.
4. Move the cursor into the panel and scroll. It stays open.
5. Move off both. **It hides almost at once.**
6. Try the other folders, and a folder's name instead of its icon.
7. Press **fn F11** again to bring your windows back. Over windows, nothing happens.

Then paste this, especially if anything didn't work:

```bash
grep -E "hover|panel|unrecognised" ~/Library/Logs/Glimpse.log | tail -30
```

For more detail when something doesn't work, turn on logging of every check and relaunch:
`defaults write local.glimpse.app verboseHoverLog -bool true; pkill -x Glimpse; open ~/Applications/Glimpse.app`.

## Worth knowing

- **The panel never covers the icon you're resting on**, so the detector can't lose it. Checks are skipped while the
  cursor is on the panel.
- **The cursor-watching timer for hiding runs only while a panel shows.** The detector's own 50 ms timer runs
  whenever previews are on: that's the 0.1 % CPU above.
- **Switching Spaces hides the panel.** It's set to show on every Space, so without this it would follow you to a
  Space where the icon isn't.
- **`--simulate-hover` pins the panel** (it ignores the hide rule), because the real cursor is somewhere else.
